# تحلیل رقبای جهانی و سریع‌ترین محصول قابل عرضه راماچ
**تاریخ بررسی:** ۲۹ اکتبر ۲۰۲۶  
**هدف:** معماری یک ویزارد واحد که تصاویر، نقشه‌ها و داده‌های اولیه پروژه را به گزینه‌های قابل اندازه‌گیری، مدل، گزارش و سپس مدارک مهندسی و مدیریت پروژه تبدیل کند.

## نتیجه مدیریتی
بازار جهانی از مرحله «AI برای رندر» عبور کرده است. موتورهای جدی برای طرح اولیه، پلان، BIM، مستندات Revit، متره، تحلیل سازه و بخشی از تأسیسات وجود دارد. با این حال این موتورهای تخصصی یک محصول قابل فراخوانی یکسان نیستند؛ برخی API سروری، برخی افزونه دسکتاپ و برخی فقط پنل و خروجی فایل دارند. فضای رقابت راماچ در **پرونده واحد پروژه + گردش کار یکپارچه، تصمیم‌پذیر، قابل ردیابی و متناسب با مقررات/قیمت‌های ایران** است. این تحلیل از مستندات رسمی است و آزمون end-to-end یا مجوز اتصال تجاری محسوب نمی‌شود.

## معیار انتخاب
- ارزش واقعی خروجی: ابعاد، اجزای قابل ویرایش، IFC/BIM، محاسبه، شیت و منشأ؛ تصویر زیبا به‌تنهایی کافی نیست.
- امکان اتصال: API عمومی تأییدشده، افزونه/SDK داخل محصول، صرفاً تبادل فایل یا اتصال غیرمستند.
- بلوغ: محصول قابل استفاده اکنون در برابر بازاریابی/بتا/دسترسی سازمانی.
- تناسب با ایران: ضوابط شهری و ملی، واحدهای متره، پرداخت و دسترسی منطقه‌ای، ریسک مالکیت داده.

## اصلاح ادعاهای مهم
1. وجود خروجی IFC در یک سرویس به معنی مجوز اجرای آن به صورت API پشت ویزارد نیست: اسناد Snaptrude می‌گویند خروجی‌های BIM سروری مانند RVT/IFC/DWG از طریق Plugin API بایت قابل دریافت برنمی‌گردانند.
2. قابلیت AI تولید پلان Finch برای اشتراک‌های پایه فعال نیست و مستندات آن به مشتریان استراتژیک/Enterprise اشاره می‌کنند.
3. Autodesk Revit Public MCP Server در ۲۰۲۶ هنوز **Technical Preview / Read-Tools** برای Revit 2027.2 است؛ API کامل ساخت و ویرایش Revit از آن استنباط نشود. گزینه رسمی اتوماسیون بدون UI سرویس Autodesk APS Automation for Revit است.
4. برای تحلیل مهندسی، موتور محاسبات می‌تواند دقیق باشد اما ورودی‌های بارگذاری، خاک، زلزله، اتصالات، نوع مصالح و استاندارد باید توسط متخصص تعیین/بررسی شوند. هیچ خروجی بدون بررسی صاحب صلاحیت، مدرک قابل امضا نیست.
5. اتصال API از داخل ایران، پرداخت و مجوز white-label، محل میزبانی و ممنوعیت‌های منطقه‌ای را پیش از فروش یا وابستگی معماری باید آزمود.

## پیشنهاد محصول سریع: «RAMACH Concept Pack»
**مخاطب نخست:** دفتر معماری کوچک/متوسط؛ **تیپ نخست:** یک ساختمان کم‌ارتفاع مسکونی/ویلایی با ابعاد مشخص. تعمیم به همه تیپ‌ها در نسخه اول ممنوع.

**ورودی ویزارد:**
- نام پروژه، نوع کاربری، موقعیت کلی، مساحت و **پلیگون/ابعاد واقعی زمین**، جهت شمال، ارتفاع/تعداد طبقات مطلوب.
- عکس‌های سایت و نمونه سبک، فایل پلان موجود اگر هست؛ عکس سایت فقط برای زمینه بصری است و جایگزین برداشت دقیق نمی‌شود.
- برنامه فیزیکی: تعداد اتاق، فضاهای ضروری، مساحت هدف، بودجه و محدودیت‌ها.
- ضوابط معلوم/تأییدشده توسط کاربر: تراکم، عقب‌نشینی، پارکینگ، محدودیت ارتفاع. سامانه باید وضعیت «تأییدنشده» را نشان دهد.

**جریان و خروجی:**
1. AI داده‌ها و تصاویر را ساختاری می‌کند، کمبودها را می‌پرسد؛ کاربر اطلاعات حساس هندسی و ضوابط را تأیید می‌کند.
2. موتور پارامتریک/قواعد محدود، ۲ یا ۳ سناریوی واقعی را روی محدوده زمین تولید می‌کند: جانمایی کلی، جدول فضا و متراژ و محدودیت‌ها. در شروع می‌توان از خانواده پلان‌های الگویی و چیدمان قابل اصلاح استفاده کرد، نه وعده تولید خودکار هر پلان.
3. یک هندسه مشترک نمای 2D و حجم 3D می‌سازد؛ نما/رندر AI از اسکرین‌شات هندسی هدایت می‌شود. خروجی رندر صرفاً کانسپت است و ممکن است جزئیات ساختمانی را تغییر دهد.
4. یک **Concept Report PDF** با شرح پروژه، گزینه‌ها، جدول مساحت و فرضیات، تصاویر و **بازه برآورد اولیه** تولید می‌شود؛ بدون ادعای نقشه مجوز یا متره اجرایی.
5. هر سناریو و تأیید کاربر با Project ID، شناسه گزینه، نسخه، زمان و منشأ ذخیره می‌شود؛ فایل‌های IFC/GLB/DXF در نسخه‌های بعد/در صورت آماده بودن صادر می‌شوند.

**هسته تکنیکی پیشنهادی:** JSON پایدار پروژه/فضا/هندسه/نسخه به عنوان مدل مبنا؛ وب‌ویزارد + Three.js برای 2D/3D سریع؛ مولد IFC مبتنی بر IfcOpenShell در مرحله بعد؛ AI صرفاً برای فهم بریف، استخراج داده، تولید توضیحات و render؛ عملیات ابعادی/مساحتی را کد قطعی انجام می‌دهد. Kreo و SkyCiv و APIهای بیرونی در شاخه اختیاری و مرحله‌ای اضافه شوند، نه وابستگی اجباری نسخه اول.

**اتصال محصولات موجود:** آرچیار = برداشت/هم‌ترازی و مشاهده روی سایت؛ چیدو = چیدمان و نمایش مبلمان؛ کیچیار = طراحی آشپزخانه و فهرست اقلام؛ کمچه = متره اجرایی/نیرو/خرید در فازهای دیرتر؛ موتور مقررات ملی = بازیابی و ارجاع بندها بعد از تکمیل و اعتبارسنجی؛ هر اپ با Project ID و نسخه مشترک همگام شود. این اتصالات فعلاً طراحی پیشنهادی‌اند، نه قابلیت تولیدی آماده.

**تخمین اجرایی مشروط** (تلاش متمرکز، کدهای موجود قابل استفاده، یک تیپ پروژه):
- ۲–۳ هفته: دموی کارکردی از داده واقعی تا ۲ یا ۳ گزینه، 3D ساده و PDF.
- ۶–۱۰ هفته: بتای محدود قابل ارائه به ۲–۳ دفتر، با اصلاح پلان، حفظ نسخه، تست ضوابط و QA دستی.
- پس از آن: خروجی IFC صحیح، نقشه‌های اندازه‌گذاری‌شده، متره قابل اتکا، اتصال ابزارهای سازه/تأسیسات، کنترل تداخل و گردش تصویب؛ زمان و هزینه مستقل و بیشتر.
این زمان‌ها تخمین تحلیلی‌اند، نه تعهد اجرا، و برای برنامه‌نویسی پیوسته است نه چند ساعت پراکنده در هفته.

**درآمد:** فروش پکیج به ازای پروژه با تحویل انسانی کنترل‌شده، سپس اشتراک دفتر برای مدیریت و نسخه‌ها. خدمت صرفاً تصویرسازی سریع‌تر است ولی مزیت رقابتی ضعیف‌تری دارد؛ «پلان مفهومی قابل ویرایش + حجم هماهنگ + گزارش مساحت و محدودیت» خروجی متمایزتر و قابل تکرار است.

## آزمایش قبل از ساخت محصول بزرگ
یک زمین واقعی با ابعاد/محدودیت معلوم و یک طراحی دستی مرجع انتخاب شود. معیارها: خطای هندسه و متراژ، درصد رعایت قیود، زمان اصلاح معمار، یکسان‌ماندن هندسه در 2D و 3D، و کیفیت/قابلیت استفاده گزارش. هر بخش «هوشمند» که مقیاس/ایمنی را تخریب کند باید غیرفعال یا دستی شود. اعتبارسنجی مقررات و سازه مسئولیت مهندس است.
