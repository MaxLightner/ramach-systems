# نقشه بازار هوش مصنوعی و خدمات دیجیتال چرخه ساختمان
پژوهش برای راماچ سیستم — نسخه ۱، ۲۹ اکتبر ۲۰۲۶

## مسئله تحقیق
هدف، پیدا کردن **همه خدمات قابل ارائه به شرکت‌های معماری و مهندسی ساختمان** است؛ چه یک شرکت آن‌ها را یکجا عرضه کند و چه شرکت‌های مختلف فقط بخشی از چرخه را پوشش دهند. پرسش اصلی «آیا می‌توان یک ویزارد/سامانه واحد ساخت که داده پروژه را بین ابزارهای موجود جابه‌جا کند؟» است، نه صرفاً «کدام شرکت هوش مصنوعی دارد؟».

سه سند:
- [کاتالوگ ۵۹ سرویس ایرانی و خارجی](service-catalog.md): حوزه، خروجی، ادعای AI، وضعیت اتصال، منبع رسمی.
- [نقشه اتصال و آزمون عملی](integration-map.md): API/SDK/MCP، شرایط اتصال و طرح آزمایش.
- [تحلیل رقبای جهانی و طرح سریع‌ترین ویزارد راماچ (۲۹ اکتبر ۲۰۲۶)](global-benchmark-and-mvp-2026-10-29.md): وضعیت واقعی اتصال، ریسک‌ها، مراحل و هزینه زمانی MVP.
- همین صفحه: جمع‌بندی، زنجیره خدمات، خلأها و اولویت‌های بررسی.

## تعریف دقیق قابلیت
- **AI مولد/عامل:** ساخت گزینه طراحی، استخراج اطلاعات، پاسخ مستند یا اجرای کار با مدل زبانی/بینایی.
- **اتوماسیون قطعی:** CAD/BIM پارامتریک، تحلیل سازه، فرمول متره، قواعد کنترل و زمان‌بندی؛ ممکن است بدون AI باشد ولی برای یک سامانه هوشمند حیاتی است.
- **انسان مسئول:** تأیید نهایی ابعاد، انطباق مقررات، تحلیل ایمنی و امضای اسناد مهندسی. «تولید خودکار» معادل «طراحی نهاییِ تأییدشده» نیست.

**جمع‌بندی:** اجزای زنجیره در بازار وجود دارند اما اتصال بی‌دردسر آن‌ها، اعتبار داده در عبور از مراحل، مقررات محلی و یک تجربه ساده «از بریف تا تحویل» هنوز مسئله است. این نتیجه **استنباط تحلیلی از پوشش محصولات** است، نه ادعای اینکه هیچ رقیبی چنین محصولی ندارد.

## نزدیک‌ترین الگوهای جهانی
1. **Autodesk Forma** — جهت‌گیری به ابر صنعتی AEC: طراحی، داده، ساخت، متره و ارتباط با Revit؛ وسیع‌ترین اکوسیستم در این فهرست، ولی همه مراحل به صورت عامل مستقل و خودکار نیستند. [منبع](https://www.autodesk.com/products/forma/overview)
2. **Snaptrude** — فضای طراحی معماری ابری و AI از برنامه فضایی تا مدل/مستند؛ نزدیک به تجربه ویزارد طراح. [منبع](https://www.snaptrude.com/)
3. **Hypar** — طراحی منطقی/پارامتریک ساختمان با workflow و تابع قابل توسعه؛ مناسب فهم «موتور عملیاتی پشت ویزارد». [مستندات](https://docs.hypar.io/)
4. **TestFit** — امکان‌سنجی زمین با حل‌کننده تخصصی و مسیر جدید اتصال عامل AI؛ محصول نقطه‌ای بسیار عمیق، نه مدیر کل دفتر. [منبع](https://www.testfit.io/product/integrations)
5. **Deltek / Monograph** — مدیریت شرکت معماری: قرارداد، منابع، تایم‌شیت، مالی و پروژه؛ نزدیک به «سیستم شرکت»، نه مولد نقشه. [Deltek](https://www.deltek.com/products/erp/vantagepoint/) · [Monograph](https://monograph.com/)
6. **Archdesk / Procore** — مدیریت چرخه اجرا و پیمانکار، خرید، مستندات، هزینه و وظایف؛ نه جایگزین نرم‌افزار طراحی. [Archdesk](https://archdesk.com/) · [Procore](https://www.procore.com/)

## بازار ایران: الگوهای قابل مشاهده
- **مدیریت پروژه و اجرا:** مپسان، آرنوکس، مپسا، پیمان‌یار، سها و IPMP.
- **دفتر فنی و متره/قیمت:** نوین متره، عمرانیکس، آبنیار و برآوردیار.
- **مالی پیمانکار:** پروفین و مپسا.
- **ترسیم/چیدمان و تصویرسازی:** آفرث و دکورِتو.
- **توسعه اختصاصی برای شرکت‌ها:** گریدورا و پیکا (این دو را نباید SaaS عمومیِ آماده فرض کرد).

در نمونه‌های بررسی‌شده ایرانی، مسیر عمومیِ مستند برای اتصال برنامه‌نویسیِ کامل و معتبر مانند API رسمی Kreo یا SkyCiv **پیدا نشد**؛ «پیدا نشد» به معنی «وجود ندارد» نیست. قابلیت‌ها بر اساس صفحات خود عرضه‌کنندگان هستند و اجرای عملی، تعداد کاربران، کیفیت و به‌روزبودن آن‌ها مستقل آزموده نشده است.

## معیارهای واقعی برای ساخت سامانه تجمیع‌کننده
برای هر ابزار، این هفت سؤال باید جواب داده شود:
1. ورودی ماشین‌خوان: PDF/DWG/DXF/IFC/RVT/JSON/عکس/متن؟
2. خروجی قابل پردازش و با شناسه پایدار: مختصات، اجزا، کمیت، تاریخچه تغییرات، نه فقط تصویر؟
3. اتصال رسمی: API عمومی، SDK، webhook، MCP، افزونه دسکتاپ، خروجی فایل، یا هیچ‌کدام؟
4. شرایط حقوقی: مجوز استفاده تجاری، حق ادغام محصول/white-label، سقف مصرف، منطقه مجاز، محل نگهداری داده؟
5. دقت و کنترل: معیار سنجش، خطا، محدودیت، مسئول تأیید، log و برگشت‌پذیری؟
6. نسخه و وابستگی: cloud/on-prem، Revit/Archicad license، GPU، اتصال اینترنت، تحریم/پرداخت؟
7. اقتصاد: قیمت استفاده مستقل، هزینه API، داده واردشده، هزینه اصلاح دستی؟

## معماری مرجع (فرضیه، نه محصول ساخته‌شده)
- **پرونده مرکزی پروژه:** اطلاعات کارفرما، سایت، ضوابط، نسخه‌ها، فضاها، اعضای BIM، فایل‌ها و تصمیم‌ها.
- **ویزارد مرحله‌ای:** سؤال‌های مشخص، تولید چند گزینه و دروازه تأیید مهندس در نقاط پرریسک.
- **موتور اتصال:** آداپتور برای IFC/BCF/DXF/PDF و APIهای رسمی؛ ثبت منشأ داده هر خروجی.
- **موتور محاسبات قطعی:** متره، کنترل ابعادی، قواعد ضوابط و فراخوانی حل‌کننده‌های معتبر.
- **عامل AI:** تفسیر بریف، استخراج نقشه و سند، انتخاب ابزار مناسب، توضیح و گزارش؛ بدون دورزدن تأییدهای مهندسی.
- **گردش کار دفتر:** نقش، ارجاع، صورت‌جلسه، زمان، هزینه و در آینده فروش/منابع.

خدمات AR/VR موجود در مجموعه (آرچیار، چیدو و کیچیار) در این تصویر به‌صورت «مصرف‌کننده/نمایش‌دهنده داده پروژه» دیده می‌شوند؛ تحقیق بازار فعلاً درباره بلوغ ابزارهای مستقل است.

## نتیجه عملی مرحله اول
پیش از ساختن کل سیستم، یک زنجیره قابل‌آزمون انتخاب شود: **ورود PDF پلان ← تشخیص اجزای معماری ← اصلاح انسانی ← متره ← قیمت‌گذاری با فهرست‌بهای محلی ← ثبت نسخه و تأیید**. برای ورودی/تشخیص می‌توان Kreo API را ارزیابی کرد؛ برای تبادل آزاد BIM از IFC/IfcOpenShell؛ برای تحلیل سازه SkyCiv API یک گزینه مطالعه است. این‌ها **گزینه آزمون** هستند، نه قرارداد همکاری یا تضمین سازگاری در ایران.
