# نقشه فنی اتصال سرویس‌های ساختمان به یک ویزارد مشترک

**مرور رسمی: ۲۹ اکتبر ۲۰۲۶**. این سند برای تشخیص «قابل‌استفاده به‌عنوان موتور پشت محصول» از «فقط قابل‌استفاده در وب‌سایت فروشنده» است. هیچ‌یک از اتصال‌های زیر هنوز در محیط راماچ اجرا یا با داده واقعی تست نشده‌اند.

## مراتب اتصال
1. **REST/GraphQL/SDK رسمی:** قابل فراخوانی از backend؛ با احراز هویت، سقف مصرف و قوانین فروشنده.
2. **MCP رسمی:** ابزارهایی که یک عامل AI می‌تواند صدا بزند. MCP محلی Revit/Archicad **به معنی API ابری چندمشتری نیست**.
3. **افزونه و تبادل فایل:** خروجی PDF/IFC/DXF/BCF/RVT/JSON؛ نیازمند نگاشت و گاهی اجرای دسکتاپ.
4. **پنل آنلاین:** صرف وجود ابزار یا پلن اشتراک، ادغام آن در اپ ثالث را اثبات نمی‌کند.

### جزئیات نمونهٔ Kreo (وجود API از مستندات رسمی تأیید شده)
- مسیر پایه تشخیص: `https://takeoff.kreo.net/api/ai-search/v1/takeoff2D`.
- مراحل: آپلود فایل → ایجاد پروژه → اجرای تشخیص → دریافت هندسه/کمیت ساختاری.
- طبق راهنما دیوار و خط از نظر مختصات/طول/ضخامت، و فضاها از نظر مساحت/محیط قابل بازیابی‌اند.
- **دسترسی API ممکن است در سطح Enterprise باشد**؛ مستند API به‌تنهایی تضمین دسترسی در همه اشتراک‌ها نیست. [راهنمای پلن](https://help-takeoff.kreo.net/en/articles/9539977-set-up-your-first-subscription).

### جزئیات Procore
- مسیر REST مستند و sandbox برای آزمایش اپ ثبت‌شده دارد؛ احراز هویت OAuth 2.0.
- سرور Procore داده پروژه را در اختیار یک سامانه ثالث می‌گذارد؛ با مجوز مشتری.
- قابلیت‌های Agentic / MCP و Semantic Agent APIs اعلام شده‌اند، ولی برخی «در طرح آزمایشی/در حال ارائه» هستند؛ عرضه عمومی هر قابلیت را جدا بررسی کنید. [مستندات](https://developers.procore.com/documentation/content/introduction).

| آزمون | ورودی ثابت | خروجی قابل سنجش | معیار شکست |
|---|---|---|---|

| BIM به کنترل | مدل کوچک IFC با چند خطای عمدی | خطاها + موقعیت/ماده/قاعده/درجه قطعیت | ادعای «تأیید مقررات» بدون مرجع و مرور مهندس |

| اتصال سرویس ابری | حساب آزمایشی و داده ساختگی | فراخوان موفق، برگشت خطا، صورت‌حساب مصرف | نقض مجوز، هزینه نامشخص، انتقال داده حساس |

## اولویت بررسی برای نمونه قابل‌نمایش
**اولویت فنی، نه تعهد به خرید یا تصمیم تجاری قطعی:**
1. **Kreo + موتور متره محلی:** چون یک مسیر تست انتهابه‌انتها از «پلان PDF» تا «اعداد قابل ویرایش» می‌دهد.
2. **IFC/IfcOpenShell + Speckle:** برای پرونده مستقل از فروشنده، تغییر نسخه و تبادل بین BIM و AR.
3. **SkyCiv:** یک proof-of-concept تحلیل سازه با مدل بسیار ساده و مقایسه با جواب کنترل‌شده؛ نه محاسبه نهایی برای ساخت.
4. **BIMcollab/Trimble:** برای انتقال issue/تصمیم/متادیتا؛ وقتی سامانه چندمهندس و چندنرم‌افزار شد.
5. **Procore/Fieldwire:** برای اتصال عملیات اجرا؛ برای بازار ایران، ارزش اقتصادی و محدودیت دسترسی باید جدا سنجیده شود.
6. **Revit/Archicad MCP:** به‌عنوان کانکتور اختیاری دسکتاپ برای شرکت‌های دارای لایسنس، نه هسته اجباری پلتفرم.

## مخاطراتی که قبل از ادغام باید رفع شوند
- **قانونی/لایسنس:** API ≠ مجوز white-label. Terms، پردازش داده مشتری، بازفروش و استفاده منطقه‌ای جدا بررسی شوند.
- **دقت:** LLM نباید جای solver، نقشه تأییدشده یا متن رسمی مقررات را بگیرد؛ نتیجه باید provenance داشته باشد.
- **منطقه:** API/پرداخت ابری ممکن است از ایران دسترس‌پذیر یا قابل خرید نباشد؛ این تحقیق هنوز تست اتصال از ایران ندارد.
- **فرمت:** PDF یک تصویر/سند است، IFC موجودیت BIM؛ تبدیل بدون پرسش از هندسه/لایه/واحد قابل اعتماد نیست.
- **هزینه و ریسک حبس فروشنده:** تعداد فراخوان، مصرف GPU/credits، سقف نرخ، ذخیره مدل و خروج داده باید قابل پیش‌بینی باشد.
- **حریم و امنیت:** نقشه‌های مشتری، اطلاعات مالی و فایل اسکن کارگاه باید در tenant جدا با رضایت و دسترسی حداقلی ذخیره شوند.
- **محصولات Beta:** MCPهای Revit و Archicad فعلاً مرحله آزمایشی‌اند؛ محدودیت تغییر API/قابلیت دارند.

## تصمیم‌های باز برای تحقیق مرحله دوم
- بررسی عینی trial/API key برای Kreo، SkyCiv و Procore و جدول هزینه واقعی هر پروژه.
- نمونه‌برداری ۲۰ پلان ایرانی با فرمت‌های متنوع برای دقت تشخیص.
- بررسی اجازه استفاده تجاری و white-label قراردادهای مربوط.
- تست خروجی DXF/IFC/BCF و حفظ ID اجزای مدل در رفت‌وبرگشت.
- بررسی پشتیبانی مقررات ملی و فهرست‌بهای ایران؛ این ویژگی را فعلاً نباید از محصولات خارجی فرض کرد.
- مقایسه با دست‌کم ۵ دفتر معماری در اندازه کوچک، متوسط و بزرگ قبل از توسعه وسیع.
