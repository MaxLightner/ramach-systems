## Four opportunity zones to investigate next

### 1. Project Identity as the backbone

The key object is not “user” or “app”; it is a project.

A project ID could link:
- site + coordinate system
- owner / architect / contractor / workforce
- model versions
- AR anchors / spatial calibration
- timeline and evidence
- material/product selections
- procurement
- public portfolio
- AI-generated alternatives and validations

Why it may matter:
- makes current apps interoperable
- creates data required by future AI
- creates verified professional history
- makes switching costs come from accumulated useful context rather than lock-in

Risk:
- users will not maintain another project database unless one workflow is immediately valuable.

### 2. Luxury / complex-site visualization as a commercial wedge

For villas on gardens, slopes, mountains or visually sensitive sites:
- capture existing context
- preserve trees/terrain visually
- place proposed building
- create cinematic imagery/video
- VR walkthrough
- on-site AR review

This can start as a service business and later feed structured site/project context into software.

Why it is interesting:
- customer value is easy to understand
- matches RAMACH's strong 3D background
- can create high-quality case studies
- does not require pretending the whole engineering stack is automated

### 3. Execution evidence + professional reputation

Instead of “social network for construction,” create a graph where:
- a professional is linked to a verified project role
- a contractor is linked to actual work packages
- a supplier is linked to actual installed/selected products
- a project timeline becomes evidence
- completed project data can selectively become portfolio proof

Potential network effect:
More project work → richer verified graph → better matching/trust → more project work.

This must be privacy/permission aware.

### 4. Evidence-based AI engineering

Build the substrate before the claim:
- local regulation corpus
- structured site constraints
- editable geometry
- validators
- benchmark projects
- professional review loop

First goal is not “AI designs a building.”
First goal is “AI performs one engineering/design task to a measurable standard and shows its evidence.”

## What NOT to build first

1. a generic architect social feed
2. a generic contractor directory
3. another generic PM dashboard
4. a generic AI render generator
5. a generic 360 virtual-tour service
6. an all-in-one platform before a recurring wedge is proven

## Beachhead candidates to validate

### A. Luxury villa / custom residential
Pros:
- strong need for visualization and owner communication
- site context matters
- higher willingness to pay
- VR/GS/camera tracking can feel premium
- can later test AI planning and Archiyar

Cons:
- potentially service-heavy
- smaller project count than mass market

### B. Architecture firms
Pros:
- repeat projects
- strong need for client presentation and model continuity
- potential plugin/workspace distribution

Cons:
- designers already use many tools
- high interoperability expectations

### C. Mid-size contractors/developers
Pros:
- recurring execution pain
- project history, evidence and coordination have measurable value

Cons:
- harder sales/onboarding
- generic PM competition
- field adoption risk

### D. Industrial / large projects
Pros:
- high-value use cases for visualization, reality capture and digital records

Cons:
- longer sales cycle
- enterprise security/integration requirements
- stronger global competition

## Current recommendation

Do not decide the company definition from competitor lists yet.

Next research should validate two things in parallel:
1. **buyer/wedge:** who will pay first and for what recurring outcome?
2. **platform core:** what minimum shared project model is needed to connect existing RAMACH apps without creating a giant platform prematurely?
